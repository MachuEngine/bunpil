## 모델 선정

> 후보군 선정 기준·전체 비교 데이터·판단 근거는 [MODEL_SELECTION.md](../MODEL_SELECTION.md),
> 실험 원본 데이터는 [EVAL.md](../EVAL.md) "7. 모델 비교 실험", "7.1 budget=5 재검증", "9. LangSmith
> Experiments" 절 참고. 아래는 결론만 요약.

**생성 모델 1차(2026-07) — Qwen2.5-14B 채택.** Qwen2.5-7B/14B, Llama3.1-8B, GPT-4o-mini, Qwen3.5-9B를
같은 샘플 15개와 고정 Judge로 비교했습니다. 여기서 `budget`은 재시도를 몇 번까지 허용하는지를 뜻합니다. 재시도가 없는 조건(`budget=1`)에서는
GPT-4o-mini가 우세해 보였지만, 실제 서비스 조건(`budget=5`)으로 재검증하자 7B와 14B의
속도 차이가 사실상 사라졌습니다(258.8초 vs 260.2초). 속도가 같다면 실패율(0% vs 6.7%)과
개수 충족률(1.04 vs 0.65)이 모두 뚜렷이 나은 14B를 쓸 이유가 분명해 승격했습니다.
GPT-4o-mini는 같은 조건에서 실패율이 오히려 늘고(0%→13.3%) 과다 생성 경향도 보여,
비용과 외부 의존 부담까지 함께 따져 보류했습니다. 당시 원칙은 "로컬 우선"(비용 0, 지문을
외부로 보내지 않음)이었습니다.

**생성 모델 2차(2026-10) — gpt-6-luna로 재선정, 운영 전환은 하지 않음.** 전제가 바뀌었습니다 —
RunPod 크레딧이 소진돼 운영 생성이 멈췄고, Judge는 이미 지문을 OpenAI로 보내고 있었습니다.
그래서 API 모델까지 운영 후보로 넣고 출제 품질과 운영 가능성 기준으로 다시 비교했습니다(API
호출은 OpenRouter로 통일). 같은 지문 33개로 qwen2.5:14b(로컬)·gpt-6-luna·gemini-3.8-flash를
돌린 결과, 로컬 qwen은 최종 게이트 통과율이 12.1%에 그쳤고(검색 도구를 뺀 재실행 기준, 첫 실행 15.2%) 두 API 모델은 100%였습니다.
gpt-6-luna와 gemini-3.8-flash의 품질 차이는 대부분 통계적으로 "판정 불가"였지만, 교사에게
더 해로운 치명적 오류(정답이 틀리거나 근거가 없는 경우, ≤2점 비율)가 gpt-6-luna 쪽이
낮았고(유의하진 않음) 비용이 6.6배 저렴해(세트당 $0.0034 vs $0.0224) **운영 생성 모델을
gpt-6-luna로 재선정**했습니다. 단 교사 1인·하루 10세트 규모에서는 비용 차이(약 $0.03 vs
$0.22)가 결정적이지는 않습니다. **운영 전환(설정 교체·배포)은 하지 않기로 했습니다**
(2026-10-07). RunPod 크레딧 소진으로 운영 생성 자체가 멈춰 있는 데다, 분필은 포트폴리오로
마무리하기로 해서 이 재선정 결과는 평가 결론으로만 남깁니다.
비교표 전체와 통계 방법은 [MODEL_SELECTION.md](../MODEL_SELECTION.md) 2차 선정 절, 원자료는
[EVAL.md](../EVAL.md) 참고.

**Judge 모델 1차(2026-07-21) — gpt-5.6-luna 채택.** 로컬 Qwen 계열 Judge는 몇 달간 프롬프트를
손봐도 사람 라벨과의 신뢰도가 목표치를 넘지 못했습니다. 여기서 신뢰도는 **Cohen's 카파(κ)**로
쟀습니다. LLM이 매긴 점수와 사람이 매긴 점수가 얼마나 겹치는지를 0에서 1 사이로 나타낸 값이고,
0이면 찍은 것과 다를 바 없다는 뜻입니다. 이 프로젝트의 목표치는 0.4입니다.

생성물을 고정한 채 Judge만 qwen2.5:7b에서 gpt-5.6-luna로 바꿔 비교하자 문항 품질 κ가 0.328에서
0.595로 올랐고, 구조 유사도 **MAE**(평균 절대 오차, 사람 점수와 몇 점 차이 나는지)도 1.689에서
0.600으로 줄어 채택했습니다(단, 이 비교는 Claude가 합성한 고정 골든셋 30건 기준이었고
2026-10에 더 큰 표본으로 다시 쟀습니다 — 바로 아래 참고). 생성 모델은 비용과
데이터 로컬 처리를 우선해 로컬에 두고, Judge는 채점 신뢰도를 우선해 외부 모델로 분리한
결정입니다(`JUDGE_BACKEND`로 생성 백엔드와 따로 전환할 수 있습니다).

**Judge 모델 2차(2026-10) — 오프라인 평가는 sonnet-5.5로 교체, 런타임 게이트는 gpt-5.6-luna
유지.** Judge 후보 다섯(sonnet-5.5·opus-5.5·gpt-5.6-luna·gpt-6.1-sol·
gemini-3.8-flash)을 먼저 기존 구조 유사도 사람 라벨 45건으로 걸렀으나, 신뢰구간이 겹쳐 순위를
확정할 수 없었습니다. 점추정치와 비용·역할을 기준으로 sonnet-5.5와 gpt-5.6-luna(기존 운영
Judge) 두 후보로 좁혀 91건으로 다시 비교하자 sonnet-5.5의 κ가 세 기준 모두 더 높았습니다
(정답유일성 0.87 vs 0.78, 오답매력도 0.67 vs 0.53, 근거성 0.58 vs 0.54). 그래서 **오프라인
정기 평가 Judge를 sonnet-5.5로 교체**했습니다. 런타임 구조 게이트는 당장 gpt-5.6-luna를
유지합니다 — gpt-6-luna(운영 생성 후보)와 같은 계열이라는 우려는 33쌍 비교에서 뚜렷한
편향이 검출되지 않았지만 근거가 약해, 생성 모델과 계열이 다른 Judge를 처음부터 쓰기로 했기
때문입니다. sonnet-5.5로 같이 교체하는 건 2026-10-07 결정(운영 전환 미실시, 포트폴리오로
마무리)에 따라 평가 결론으로만 남깁니다. 상세는
[MODEL_SELECTION.md](../MODEL_SELECTION.md), 원자료는 [EVAL.md](../EVAL.md) 참고.

**Judge 아키텍처 — 런타임까지 완전 분리(2026-07-23).** gpt-5.6-luna를 Judge로 처음 정할
당시에는 `JUDGE_BACKEND`가 오프라인 eval 스크립트에만 적용됐습니다. 정작 런타임에서는
생성 에이전트가 자기 출력을 스스로 채점하고 있었습니다(self-judge, 검증-배포 불일치.
배경은 [아키텍처](ARCHITECTURE.md#출제-모듈--평가-수정-루프-워크플로--분리된-judge), [엔지니어링 하이라이트](ARCHITECTURE.md#엔지니어링-하이라이트) 참고).
지금은 `JUDGE_BACKEND`가 **프로덕션 앱 실행에도 그대로 적용**되며, API 키가 없거나 호출이
실패하면 조용히 폴백하지 않고 그대로 실패합니다(fail-fast).

**VLM 모델(이미지→텍스트) — gpt-4o-mini에서 gpt-6-luna로 재선정(2026-10).** 1차 선정
(2026-08)은 다른 모델과 비교 없이 gpt-4o-mini를 채택했습니다. 2026-10에 그림 서술
Judge를 먼저 사람 라벨 130건으로 검증한 뒤(가장 정확한 Judge가 gpt-5.6-luna로 κ 0.89 vs
sonnet-5.5 0.63, 문항 품질에서 더 정확했던 sonnet-5.5와 반대였습니다. 사람 점수가 양 끝에만 있던
첫 라벨 90건에서는 κ 0.95로 과대평가돼, 결함을 넣은 서술 40건으로 중간 구간을 채워 다시 쟀습니다.
luna는 핵심 수치 오류를 약하게 봐서 품질 감시 경보 기준은 3점 이하로 정했습니다) 후보 5종(API 3종·로컬 2종)을 비교하자 네 후보
모두 gpt-4o-mini보다 뚜렷이 우세했고, 그중 gpt-6-luna가 그림 문항 CER(0.035)과 서술
실패율(0%)에서 가장 좋았습니다. 운영 VLM을 gpt-6-luna로 재선정했고 1단계(코드 기본값
전환)는 적용했습니다. 로컬 qwen3-vl:8b-instruct로 옮겨 이미지 외부 전송(하드룰 2 예외)을
없애는 2단계는 운영 전환을 하지 않기로 해 더 검토하지 않습니다(이미지 외부 전송 예외를
없애는 방안으로 기록만 남깁니다). 비교 방법과 수치는 [MODEL_SELECTION.md](../MODEL_SELECTION.md) §7
"2차 선정", 원자료는 [EVAL.md](../EVAL.md) 29절 참고.

## 품질 평가

> **더 알고 싶으면 → [EVAL_SUMMARY.md §0 "이것만 기억하면 된다"](../EVAL_SUMMARY.md#0-이것만-기억하면-된다)** (1스크롤).
> 관리 지표는 50개지만 **합격선이 걸린 건 4개**뿐이고, 나머지는 게이트가 깨졌을 때 원인을 쪼개 보는 값입니다.
> 회차별 원본 로그는 [EVAL.md](../EVAL.md) — 시간순 실험 로그라 뒤 절이 앞 절을 뒤집는 곳이 있어, 어디가 그런지는 그 문서 0절에 색인해 뒀습니다.

아래 4개가 헤드라인입니다(2026-10-04 정기 평가 기준으로 갱신). **측정 조건이 행마다 다르니 세 번째 열을 같이 읽어 주세요.**

검색은 현재 배포 구성(RAG 파이프라인, LLM과 무관)에서 잰 값입니다. Judge 신뢰도와 생성 모델별
점수는 2026-10에 사람 라벨 91건(qwen2.5:14b·gpt-6-luna·gemini-3.8-flash 세 모델 × 지문
33개에서 뽑은 객관식 문항)으로 새로 측정했습니다. 날짜: 검색 2026-08-03, Judge 신뢰도·생성
모델 비교 2026-10-04.

| 지표 | 값 | 의미 |
|---|---|---|
| 검색 Recall@5 | **1.000** [1.0, 1.0] (MRR 0.854 [0.732, 0.955]) | RAG 파이프라인이 실제로 관련 문서를 찾아온다는 근거. n=22, 천장 도달 |
| Judge 신뢰도 (Cohen's κ, 오프라인 sonnet-5.5, 사람 라벨 91건) | 정답유일성 **0.86** [0.74,0.94] 확정 · 오답매력도 **0.70** [0.60,0.77] 확정 · 근거성 **0.56** [0.35,0.73] 미확정 | 오프라인 평가 Judge 채점이 사람 라벨과 일치한다는 근거. 아래 품질 점수들은 이 신뢰도에 기대어 읽어야 합니다 |

| 〃 — 로컬 **qwen2.5:14b**(현재 기본값) | 정답유일성/오답매력도/근거성 **2.96 / 2.48 / 3.28** (n=25) | 같은 비교에서 API 두 모델에 모두 뚜렷이 뒤짐(신뢰구간이 0을 포함하지 않음) |

> **용어 세 가지만 먼저 풀어 둡니다.**
> **Recall@5**는 정답 문서가 검색 상위 5개 안에 들어온 비율입니다(1.000이면 전부 들어왔다는 뜻).
> **MRR**은 몇 번째로 올라왔는지까지 보는 값으로, 1위면 1점 2위면 0.5점 식으로 매긴 평균입니다.
> **Cohen's 카파(κ)**는 LLM 채점과 사람 채점이 얼마나 겹치는지를 0~1로 나타낸 값입니다. **신뢰구간(CI)**은
> "같은 측정을 반복하면 참값이 이 범위 안에 들어올 가능성이 크다"는 구간이고, 표에서는 `[하한, 상한]`으로
> 표기합니다. 아래 "확정/미확정/판정 불가"는 CI를 기준으로 가른 판정입니다 — **확정**은 목표 임계값을
> CI 하한까지 넘은 경우, **미확정**은 점추정치는 넘었지만 CI 하한이 임계값에 못 미치는 경우, **판정 불가**는
> CI가 0(또는 비교 대상)을 포함해 방향조차 가릴 수 없는 경우입니다.

> **옛 수치 0.468·4.06·3.14는 왜 사라졌나** — 셋 다 Claude가 문항과 점수를 모두 합성한 고정
> 골든셋(ITEM_GOLDEN, 30문항) 기준이었습니다. 0.468은 그 골든셋으로 잰 Judge 신뢰도(κ)인데
> 같은 Judge·같은 30건에서도 실행마다 0.468/0.595로 흔들렸고, 4.06은 그 골든셋 자체를 채점한
> 점수라 애초에 **생성 품질이 아니었습니다**(전/후 평균이 소수점까지 동일하게 나와서 발견 —
> [EVAL.md](../EVAL.md)). 3.14는 실제 생성물을 쟀지만 **qwen2.5:7b·budget=1·n=24**라는 작고
> 불리한 조건이었고, CI로 다시 계산하면 [2.74, 3.58]로 폭이 넓어 참고용이었습니다(옛 기록은
> 아래 상세 접기에 CI와 함께 남겨 뒀습니다). 2026-10부터 **실제 생성물(3모델) + 사람 라벨
> 91건**으로 측정 방식을 바꿔 위 표의 값으로 대체했습니다.

- 검색 수치는 LLM과 무관합니다. BM25 + BGE-M3 + 리랭커 파이프라인 자체의 성능입니다
- **검색 개선 2단(2026-08-03)** — Recall@5가 처음 1.000에 도달한 과정이 두 단계였고, **효과가 큰 쪽은 두 번째**였습니다:
  1. **하이브리드 검색**: 의미 기반 검색(dense)만 쓰던 것에 단어 기반 검색(BM25)을 더해 순위를 RRF로 합쳤습니다. 새 모델·재인덱싱 없이 BGE-M3 토크나이저와 기존 청크 텍스트만 사용. 전체 MRR 0.789→0.814로 올랐지만 **원래 목표였던 regulations MRR(0.667)은 꿈쩍하지 않았습니다** — dense가 후보에조차 못 올리던 청크를 BM25가 찾아냈는데 리랭커가 top-5로 올리지 못했기 때문
  2. **`n_candidates` 20→10**: 리랭커를 조사하다 통념과 **반대** 결과를 만났습니다. 후보를 많이 줄수록 나빠집니다(10/20/30/50 → Recall@5 1.000/0.955/0.955/0.909). 리랭커가 후보가 늘수록 오답을 상위로 잘못 올리는 것으로 보입니다. 골든 22건 전수 대조에서 **개선 3건·악화 0건**, 리랭커가 순위를 매길 쌍이 절반이라 **속도도 2배**
  - 최종: 전체 Recall@5 **1.000**·MRR **0.854**, regulations Recall@5 **1.000**·MRR **0.753**. 리랭커 ablation도 함께 측정해 "리랭커 기여도 미측정" 항목을 닫았습니다(MRR +0.034~0.045, Recall엔 영향 없음). 상세는 [EVAL.md](../EVAL.md) 12·13절
  - ⚠️ **Recall@5 1.000은 "이 22건에서 전부 찾았다"는 뜻**이지 검색이 완벽하다는 뜻이 아닙니다. 이제 이 골든셋으로는 추가 개선을 측정할 수 없어(천장 도달) 더 어려운 골든셋이 필요합니다
- **Judge 신뢰도 측정 방법이 2026-10에 바뀌었습니다.** 예전 κ 0.468(2026-07-24, n=30)은 Claude가
  문항과 점수를 모두 합성한 고정 골든셋(ITEM_GOLDEN) 기준이었고, 같은 Judge·같은 30건에서도
  실행마다 0.468/0.595로 흔들렸습니다. 지금은 **실제 생성물 + 사람 라벨 91건**(qwen2.5:14b·
  gpt-6-luna·gemini-3.8-flash 세 모델 × 지문 33개에서 뽑은 객관식 문항)으로 측정하고, 오프라인
  평가 Judge도 gpt-5.6-luna에서 sonnet-5.5로 교체했습니다(선정 근거는 [모델 선정](#모델-선정)).
  ITEM_GOLDEN 기준 κ·종합평균(0.468·4.06)은 폐기했습니다
- 생성물 기준 수치는 한동안 `experiments/`의 **일회성 A/B로만** 산발적으로 재 왔습니다. 오답매력도는 3.82였고, 정답유일성은 텍스트 지시가 통하지 않았습니다(p=0.58, 관찰된 차이가 우연일 가능성이 58%라 효과를 인정할 수 없다는 뜻). few-shot으로는 3.091에서 **3.875**까지 올랐지만 아직 미확정입니다 — 이 항목들은 모두 2026-09 이전, qwen2.5:7b 기준 기록입니다
- ⚠️ 위 값들은 표본도 조건도 제각각입니다. 2026-09-07 정기 관측치(오답매력도 3.29, 정답유일성
