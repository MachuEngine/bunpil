## 1. 대표 사용자 작업

### 생성 모델이 하는 일

| ID | 작업 | 호출 방식 | 입력 → 출력 | 코드 |
|---|---|---|---|---|
| G-T1 | **문항 세트 생성** | ReAct 에이전트, tool calling 다회(최대 14턴 × 재시도 최대 5회) | 예시 문제(수백~8,000자) → 도구 호출로 문항 N개 저장(기본 2개) | `app/modules/exam/graph.py` |
| G-T2 | **해설 생성** | 단발 호출 | 문항 1개(~1,000자) → 해설 텍스트(~500~1,000자) | `explain.py` |
| G-T3 | **대화형 수정** | 단발 호출(+1회 재요청), JSON 출력 | 예시·문항 세트·대화 6턴·요청 → 바뀐 문항 JSON | `revise.py` |
| G-T4 | 요청 문항 수 추출 | 단발 호출, 숫자만 출력 | 입력 텍스트 → 정수 | `main.py _analyze_request`(형식 판정과 한 호출) |

G-T1의 예시 형식은 5종이다: 4지 단순형, 5지 단순형, `<보기>` 합답형, 자료 제시형, 서술형.

### Judge 모델이 하는 일

| ID | 작업 | 사용처 |
|---|---|---|
| J-T1 | **런타임 구조 채점** — 생성 세트가 예시의 유형·난이도·주제를 유지했는가(0~5, 게이트) | `judge.py judge_structure`, 매 생성 요청 |
| J-T2 | **정답 키 검증** — 정답을 보지 않고 문항을 풀어 정답 키와 비교 | 오프라인 평가(신규) |
| J-T3 | **문항 결함 판정** — 사실 오류, 발문·선지 불일치, 복수 정답 | 오프라인 평가 |
| J-T4 | **해설·수정 판정** — 해설이 정답과 일치하고 사실이 맞는가, 수정이 요청을 반영했는가 | 오프라인 평가(신규) |
| J-T5 | **pairwise 선호** — 두 모델 출력 중 어느 쪽이 나은가(익명, 위치 교환) | 모델 선정 평가 |

## 2. 작업별 중요도와 예상 트래픽 비율

호출량 기록은 없다. **[가정]** 교사 1인이 하루에 세트 10회, 해설 30회, 수정 20회를 요청한다고 본다
(세트당 문항 2~3개를 모두 해설로 확인하고 절반 정도를 수정한다는 가정). 비용은 이 값과
**교사 10명 확장 시나리오(×10)** 두 가지로 계산한다.

| 작업 | 호출 비율(요청 수 기준) | 호출당 LLM 호출 수 | 중요도 | 이유 |
|---|---|---|---|---|
| G-T1 세트 생성 | 17% | 많음(에이전트 턴 × 재시도) | **최상** | 서비스의 본 기능. 여기서 틀린 정답이 나오면 이후 해설·다운로드가 전부 오염된다 |
| G-T2 해설 | 50% | 1 | 상 | 교사가 정답을 확인하는 수단. 틀린 해설은 틀린 정답을 정당화한다 |
| G-T3 수정 | 33% | 1~2 | 중 | 실패해도 원본이 유지된다(코드가 보장) |
| G-T4 개수 추출 | 세트마다 1회 | 1 | 하 | 규칙 기반 검증이 쉽고 실패 시 기본값 2 |
| J-T1 런타임 채점 | 세트마다 1~5회 | 1 | 상 | 재시도 여부를 결정한다 |
| J-T2~T5 | 오프라인 | — | 상(선정용) | 모델 선정과 회귀 감지의 근거 |

**비용 비중은 G-T1이 가장 크다** — 입력이 매 턴 누적되기 때문이다(GPT-4o-mini 실측: 15샘플 113회
호출에 입력 329,791 / 출력 13,949 토큰, EVAL.md:665-680).

| ID | 요구사항 | 구분 | 판정 방법 |

| F2 | 한국어 출력. 한자 비율 5% 이상 오염 금지(`_check_korean` 기준) | **Hard gate** | 규칙 |
| F3 | 입력 컨텍스트 16K 토큰 이상(에이전트 누적 대화 + 예시 8,000자) | **Hard gate** | 공식 문서 |
| F4 | JSON 출력 안정성 — G-T3 수정 응답이 파싱 가능 | **Hard gate**(≥ 95%) | 규칙(JSON 파싱) |
| F5 | 세트 완성률 — 목표 개수를 채우고 0문항으로 끝나지 않음 | **Hard gate**(≥ 90%) | 규칙 |

| F7 | Judge: 구조화된 출력 — 지정 JSON을 파싱 가능하게 반환 | **Hard gate**(≥ 99%) | 규칙 |
| F8 | Judge: 생성 모델과 다른 모델. 최소 1개 후보는 다른 제공사·계열 | **Hard gate** | 설정 |
| F9 | Judge: "판단 불가"를 표현할 수 있음(rubric에 `unsure` 선택지) | Quality metric | 규칙 |

## 4. 품질 기준

### 생성 모델

| ID | 지표 | 구분 | 측정 | 기준 |
|---|---|---|---|---|
| Q1 | **정답 키 일치율** — 검증된 Judge가 독립 풀이한 답 = 정답 키 | Quality metric | Judge(J-T2) + 규칙 비교 | 높을수록 좋음 |
| Q2 | 문항 결함률 — 사실 오류·발문/선지 불일치·복수 정답 | Risk metric | Judge(J-T3) 예/아니오, 일부 사람 확인 | 낮을수록 좋음 |
| Q3 | 첫 시도 형식 통과율 + 거부 사유 분포(형식/한국어/복사/중복) | Quality metric | 규칙 | 높을수록 좋음 |
| Q4 | 해설 정확성 — 정답 일치 + 사실 오류 없음 | Quality metric | Judge(J-T4) | 높을수록 좋음 |
| Q5 | 수정 반영률 + 범위 준수(요청 안 한 문항 불변) | Quality metric | Judge + 규칙 | 높을수록 좋음 |
| Q6 | 인간 선호 — 두 모델 출력 비교 | Quality metric | 사람 pairwise(소표본) | 참고 |
| Q7 | 오답 매력도 3점 이하 비율 | Quality metric(진단) | Judge | 진단용 — 종합 점수에 넣지 않음. 개선 수단 없음으로 종결된 지표(EVAL.md 27절) |
| Q8 | 문항 개수 추출 정확도(G-T4) | Quality metric | 규칙(exact match) | ≥ 95% |

**1~5점 척도보다 예/아니오 판정과 규칙 비교를 우선한다.** 척도 점수는 특정 점수 쏠림(82%가 4점)과
Judge 간 편향(+0.94)이 반복 확인됐다(EVAL.md 26절, MODEL_SELECTION.md:61).

### Judge 모델

| ID | 지표 | 구분 | 기준(초기값) |
|---|---|---|---|
| JQ1 | 사람 gold label과의 일치 — pass/fail macro F1, weighted κ, 점수형 Spearman | Quality metric | κ ≥ 0.4(현 기준), 사람 간 일치도를 상한으로 해석 |
| JQ2 | **치명적 오류 탐지 recall** | Quality metric | ≥ 0.8 |
| JQ3 | 정상 응답 오탈락률(false reject) | Risk metric | ≤ 0.15 |
| JQ4 | 독립 풀이 정확도(J-T2) — 정답이 확정된 문항 기준 | Quality metric | ≥ 0.85 |
| JQ5 | 형식 위반 탐지율 — 일부러 형식을 어긴 문항을 탈락시키는 비율 | Quality metric | ≥ 0.8 |
| JQ6 | 반복 안정성(같은 입력 3회) · A/B 위치 교환 일치율 | Quality metric | 높을수록 좋음 |
| JQ7 | 길이·문체·자기 계열 선호 편향 | Risk metric | 낮을수록 좋음 |
| JQ8 | 판단 불가 처리 — ambiguous subset에서 `unsure`를 쓰는가 | Quality metric | 참고 |

## 5. 지연 시간과 비용 조건

| ID | 요구사항 | 구분 | 기준 | 근거 |
|---|---|---|---|---|
| L1 | 세트 생성(G-T1) 응답 시간 | **Hard gate** | **p95 ≤ 60초** | [확인] 사용자 답변 "1분 이내" |

| C1 | **성공한 세트 1건당 총비용**(재시도·Judge 포함) | Operational metric | 낮을수록 좋음 | 토큰 단가가 아닌 성공 작업 기준 |
| C2 | 월 모델 비용(교사 1인 기준) | **Hard gate** | ≤ $10 | [가정] README의 빌링 알람 기준 $10 |
| C3 | 월 모델 비용(교사 10명 시나리오) | Operational metric | 보고만 | 확장성 판단용 |
| C4 | API 실패율·재시도율 | Operational metric | 낮을수록 좋음 | |
| C5 | 자체 호스팅 후보의 콜드스타트 | Operational metric | 보고 | RunPod min workers=0이면 30~60초 추가(README:710) — L1과 충돌 가능 |

> ⚠️ **L1은 현재 구조와 충돌할 가능성이 높다.** 기존 실측은 로컬 14B 기준 세트당 111~260초였다
> (EVAL.md:2238-2270, MODEL_SELECTION.md:34). 에이전트 다회 턴 + Judge + 재시도 구조 때문이다.
> 모든 후보가 L1을 통과하지 못하면 결론을 억지로 내지 않고, 모델 교체와 구조 변경(턴 수 축소 등)을
> 분리해 보고한 뒤 기준 재조정을 사용자에게 요청한다.

## 7. 치명적 오류의 정의

아래 중 하나라도 해당하면 그 출력은 **치명적 오류**로 집계한다(Risk metric, 비율로 보고).

| ID | 오류 | 왜 치명적인가 | 검출 |
|---|---|---|---|
| X1 | **정답 키 오류** — 표시된 정답이 틀림 | 학생 채점이 틀린다. 해설이 오류를 정당화해 교사가 알아채기 어렵다 | Judge 독립 풀이 불일치 → 사람 확인 |
| X2 | **복수 정답** — 정답이 둘 이상 | 시험 문항으로 쓸 수 없다(이의 제기 대상) | Judge + 사람 확인 |
| X3 | **사실 오류** — 교육과정 개념을 틀리게 서술 | 학생이 잘못 배운다 | Judge + 사람 확인 |
| X4 | **해설-정답 불일치** — 해설이 다른 선지를 정답이라 함 | 교사 화면에서 서로 다른 말을 한다 | Judge |
| X5 | 0문항 반환 / 형식 붕괴 | 서비스 실패 | 규칙 |
| X6 | 예시 문제 복사 — 게이트 통과 후에도 의미상 복사 | 새 문항이 아니다 | 규칙 + Judge |
| X7 | PII 노출(출력에 마스킹 전 개인정보) | 하드룰 위반 | 규칙 |

**치명적 오류율 기준(초기값)**: X1+X2+X3 합계 ≤ 10%, X4 ≤ 5%, X5 ≤ 5%, X7 = 0.
현재 스택의 실측 정답유일성 2.67/5(n=24, 7B·budget=1 조건, EVAL.md:905-936)로 보아 **모든 후보가
X1~X3 기준을 넘지 못할 수 있다.** 그 경우 기준을 낮추지 않고 "상대적으로 가장 낮은 후보 + 사람 검토
필수"로 결론을 제한한다.

## 8. 모델 선정 완료 조건

1. 생성·Judge 각각 파일럿 후보 3~5개를 **같은 데이터·같은 조건**으로 실행했다.
2. Judge 후보를 사람 gold label(2인 독립, 불일치는 ambiguous subset)과 비교했고, 사람 간 일치도를 함께 보고했다.
3. 생성 모델 평가는 **검증을 통과한 Judge**로 채점했다(Judge 검증이 생성 비교보다 먼저).
4. 파일럿을 통과한 후보만 holdout test로 평가했고, holdout은 프롬프트·설정 조정에 쓰지 않았다.
5. hard gate → 치명적 오류 → 개별 지표 → Pareto → 가중 점수 → ±20% sensitivity 순서로 판단했다.
6. 모든 수치에 표본 수(n)와 신뢰구간을 붙였고, 측정하지 않은 값은 "미측정"으로 적었다.
7. 총 유료 API 비용이 $50 이하였다.
8. 최종 권장안(기본·저비용·상위 모델, fallback, 라우팅, 기본·보조 Judge, 사람 검토 조건, 재평가 조건)을
   `docs/model-selection-report.md`에 작성했다.

### 표본 크기 원칙

| 대상 | 최소 | 근거 |
|---|---|---|
| 생성 파일럿 | 입력 40개(형식 5종 × 8) | 형식별 편차 확인 |
| 생성 정식(holdout) | 모델당 문항 ~240개(입력 40 × 3회 × 2문항) | 전체 비율 ±7%p, 모델 간 약 12%p 차이 탐지(같은 입력으로 짝지어 비교) |
| Judge gold label | 100~200건(2인) | κ 신뢰구간 ±0.15~±0.1. 현재 κ 0.468은 n=30이라 신뢰구간 약 0.21~0.73 |
| Judge 형식 위반 탐지 | 60건 | ±6%p |

신뢰구간은 문항 단위가 아니라 **입력 예시 단위 부트스트랩**으로 계산한다 — 같은 요청에서 나온 문항은
서로 독립이 아니기 때문이다.
